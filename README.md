# Acquisitions API

Acquisitions is a REST API built with Node.js and Express that provides a foundation for user account management. The project currently focuses on account registration, JWT authentication, user management, PostgreSQL connectivity, and request protection.

## Technologies

- Node.js 24 and ECMAScript modules
- Express 5
- PostgreSQL through Neon Serverless
- Drizzle ORM và Drizzle Kit
- JWT and HTTP-only cookies for tokens
- bcrypt for password hashing
- Zod for input validation
- Helmet, CORS, cookie-parser, and Morgan
- Arcjet for bot protection, shields, and request rate limiting
- Winston for logging
- Jest and Supertest for API testing
- Docker and Docker Compose for development and production environments

## Available API

### System Endpoints

| Method | Endpoint  | Mô tả                                 |
| ------ | --------- | ------------------------------------- |
| GET    | `/`       | Quick server check                    |
| GET    | `/health` | Returns status, timestamp, and uptime |
| GET    | `/api`    | Checks API status                     |

### Authentication

| Method | Endpoint             | Mô tả                                                                       |
| ------ | -------------------- | --------------------------------------------------------------------------- |
| POST   | `/api/auth/sign-up`  | Creates a user, hashes the password, and issues a JWT in the `token` cookie |
| POST   | `/api/auth/sign-in`  | Endpoint is defined; sign-in logic still needs to be implemented            |
| POST   | `/api/auth/sign-out` | Endpoint is defined; sign-out logic still needs to be implemented           |

Sign-up request example:

```json
{
  "name": "Nguyen Van A",
  "email": "user@example.com",
  "password": "matkhau123",
  "role": "user"
}
```

`role` accepts only `admin` or `user` and defaults to `user`. Emails are normalized to lowercase; passwords must be between 6 and 128 characters.

### User Management

The following endpoints require a JWT through the `Authorization: Bearer <token>` header or the `token` cookie.

| Method | Endpoint         | Mô tả                                   |
| ------ | ---------------- | --------------------------------------- |
| GET    | `/api/users`     | Lists users without returning passwords |
| GET    | `/api/users/:id` | Gets a user by ID                       |
| PUT    | `/api/users/:id` | Updates name, email, password, or role  |
| DELETE | `/api/users/:id` | Deletes a user by ID                    |

User update example:

```json
{
  "name": "Nguyen Van B",
  "email": "new-email@example.com"
}
```

## Environment Configuration

Create a `.env` file or the corresponding environment file before running the application:

```env
NODE_ENV=development
PORT=3000
DATABASE_URL=postgresql://user:password@host/database
JWT_SECRET=replace-with-a-long-random-secret
JWT_EXPIRATION=1h
ARCJET_API_KEY=your-arcjet-api-key
```

Do not commit `.env` files or real secrets to the repository.

## Local Installation and Running

Node.js compatible with the current packages is required. Node.js 24 is recommended.

```bash
npm install
npm run dev
```

The server runs at `http://localhost:3000` by default.

## Database and Migrations

The user schema is defined in `src/models/user.model.js`. Drizzle commands:

```bash
npm run db:generate
npm run db:migrate
npm run db:studio
```

These commands use `DATABASE_URL` to connect to PostgreSQL.

## Running with Docker

Development with Neon Local:

```bash
docker compose -f docker-compose.dev.yml up --build
```

Production:

```bash
docker compose -f docker-compose.prod.yml up --build -d
```

The container exposes port `3000` and has a health check through `GET /health`.

## Testing and Quality Checks

```bash
npm test
npm run lint
npm run format-check
```

The current tests check the health endpoint, API status, and the 404 response for an unknown route. Jest is also configured to collect coverage in the `coverage/` directory.

## Security and Logging

- Helmet sets HTTP security headers.
- Arcjet checks for bots, shield violations, and role-based rate limits.
- Passwords are hashed with bcrypt before storage.
- JWTs are signed and verified with `JWT_SECRET`.
- The token cookie is configured with `httpOnly`, `sameSite: strict`, and `secure` in production.
- Requests and errors are logged by Morgan/Winston to `logs/combined.log` and `logs/error.log`.
